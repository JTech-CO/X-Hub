# X HUB 3.3.0 코드 점검

## 주요 수정

| 문제 | 수정 |
|---|---|
| Filter 패널에서 벗어나면 감시가 중지되고 새 탭에서 저장된 필터가 적용되지 않음 | 필터 활성 설정과 패널 모드를 분리 |
| 인용 숨김이 ALL/다른 설정으로 바꿔도 남음 | 게시물과 인용의 숨김 표시를 함께 복원하고 기존 display 값 보존 |
| API 인증 정보는 숫자 ID로 저장하지만 조회는 핸들로 함 | 핸들을 소문자로 정규화해 캐시 키 통일; 미인증 응답도 반영 |
| 인용된 사람의 뱃지가 원 게시물 작성자에게 적용될 수 있음 | 작성자 이름 영역으로 뱃지 탐색 범위 제한 |
| ISOLATED world에서 history.pushState만 패치해 X의 SPA 전환을 놓침 | URL 변경 감지로 push/replace/back 경로 처리 |
| 비스크롤 요소의 scrollHeight만 보고 자동 스크롤 대상으로 선택 | overflow와 실제 스크롤 범위를 함께 검사 |
| 한국어 팔로우 영역을 광범위하게 제외해 실제 목록도 누락 가능 | 추천/사이드바 영역만 제외 |
| 페이지 이동이나 재시작 뒤 이전 비동기 스캔이 결과를 덮어쓸 수 있음 | 스캔별 실행 ID와 시작 URL 검사 |
| 일반 팔로워 탭이 자동 수집 탭으로 오인돼 닫힐 수 있음 | 서비스 워커가 만든 탭만 session storage로 추적하고 닫기 허용 |
| 서비스 워커가 잠들면 탭 소유권이 사라짐 | chrome.storage.session 사용 |
| 팔로워/팔로잉 동시 저장 시 한쪽 화이트리스트 유실 | 서비스 워커에서 저장 직렬화 |
| 계정 변경 후 이전 계정 화이트리스트 유지 | 계정 전환 시 초기화, 수집 결과의 계정 검사 |
| fetch 인터셉터가 JSON 해석을 기다린 뒤 응답을 반환 | X에는 응답을 즉시 반환하고 복제본을 비동기 처리 |
| 필터 기본 설정을 얕게 복사해 중첩 객체 공유 | filter 속성까지 병합 |
| 툴바 버튼 메시지는 보내지만 content 수신 없음 | 패널 토글 수신 추가 |
| 닫기 후 패널 복구 불가 | 최소화와 재열기 경로 유지 |

| 외부 Google Fonts 요청 | 확장 패널의 원격 폰트 로딩 제거 |

## Vertical 구조

- `src/vertical.js`에 화면과 열 수명 주기를 분리. 원 게시물을 복제하지 않고 각 열에서 X의 원래 문서를 실행한다.
- Shadow DOM으로 확장 UI를 격리한다. 열 내부는 주 타임라인 폭과 작성자 액션 줄을 조정하고, X의 원래 메뉴와 대화창을 유지한다.
- 최대 8열 저장, 화면에 최대 5열을 맞춘다. 최소 360px 아래로 강제 축소하지 않으며 가로 스크롤과 열 확대를 제공한다.
- 같은 출처의 전용 프레임 요청에 한해 X-Frame-Options를 SAMEORIGIN으로 설정한다. CSP를 제거하거나 유료 API를 호출하지 않는다.
- X의 서비스 워커 캐시 응답에는 DNR이 적용되지 않으므로 북마크 경로에서 초기화한 후 내부 탐색으로 목표 타임라인을 연다.
- 열 이동은 CSS order로 처리해 iframe 재접속에 따른 스크롤/입력 손실을 방지한다.
- 보기 종료 시 프레임, 로딩 타이머, resize 리스너와 임시 네트워크 규칙을 정리한다.

## 검증

- `npm test`의 기능 회귀 테스트: 15개 회귀 테스트 통과.
- JavaScript 4개 파일 문법 검사 통과.
- 실제 로그인된 X/Brave에서 홈, 알림, 북마크, 탐색 4열 및 5열의 원 게시물 렌더링 확인.
- 로컬 가상 타임라인에서 좋아요 상태 변경, 열 재정렬 후 상태 보존, 850px 열 확대, 기본 화면 복귀 확인.
- 900px 화면에서 435px 열 2개와 가로 스크롤, 액션 버튼 표시 확인.
- 가상 게시물 20개 중 VERIFIED 필터로 미인증 10개 숨김, Raffle 전환 후 유지, ALL 전환 시 20개 복원 확인.
- 실제 X 열 안에서 재게시 메뉴 표시 확인. 계정의 게시·좋아요·재게시 확정 동작은 테스트로 수행하지 않았다.
- 마지막 검색·프로필·리스트 직접 경로 전환은 실제 브라우저의 확장 새로고침 후 추가 검증이 필요하다.

## 유지보수 시 주의

- X DOM, 라우팅, 서비스 워커 정책은 공개된 안정 API가 아니다. 사이트 변경 시 선택자와 초기 진입 경로를 다시 검증해야 한다.
- Raffle/Follow는 화면에 로드되는 목록을 수집한다. X의 로딩 지연·접근 제한·중단 때문에 계정 전체 목록과 일치한다고 보장할 수 없다.
- X의 프레임 차단이 CSP frame-ancestors로 바뀌면 현재 로더는 오류를 표시한다. CSP를 삭제하는 우회는 구현하지 않았다.
- 소스 폴더에 Git 메타데이터가 없어 커밋/PR은 생성하지 않았다.

## 저장소 구조 정리 (3.3.1)

- 원본을 src로, 실행 결과를 dist로 분리하고 기존 HTML과 이미지를 docs로 이동.
- 테스트는 빌드한 dist를 사용하고 수동 검증 서버는 scripts/manual로 이동.
- 문법·참조·버전 검사와 배포 ZIP 파일별 SHA-256 검사 추가.
- 폴더 정리에서는 확장 실행 코드와 매니페스트 내용을 변경하지 않음.
- Node.js 24.19.0에서 기능 회귀 15개 + 빌드 테스트 4개, 총 19개 통과.
- 배포 ZIP의 실행 파일 8개를 dist와 SHA-256으로 대조. 두 번 생성한 ZIP 해시가 동일함을 확인.
- 이동한 가상 타임라인 서버의 홈 응답(게시물 20개), 두 스크립트 응답 및 문서 내부 파일 링크 확인.
- 로컬 Node.js 25.2.0에서는 디렉터리 정리 중 프로세스 비정상 종료가 관찰되어 Node.js 24 LTS로 검증. 개발 환경은 22/24 LTS로 명시.
